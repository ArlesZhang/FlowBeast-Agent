## F1 — GRAFT 传递的是常量，不是结构 `[REPRO]`

结构逐字节相同。只有 `opening_line` 变了——而它之所以会变，只是因为这个字段回退到了检索记录里的 `hook` 文本。

**根因。** [`fp3_meta.json`](../../flowbeast/data/outputs/vector_store/fp3/fp3_meta.json) 里 60 条记录：40 条是 `PromptAtom` 键集 `(atom_id, embedding, layer, prompt_fragment, role, source, tags, version, vto_metadata)`，20 条是 `(emotion, hook, pattern)`。**没有任何一条记录包含 `hook_structure` 或 `conflict_pattern` 键。**

所以 [graft.py:120](../../flowbeast/vto/graft.py#L120) 这行：

```python
hs = viral_script.get("hook_structure", {})   # 永远是 {} → 每个 .get() 的默认值都会触发
```

`_extract_hook_structure` 和 `_extract_conflict_pattern` 里每一个 `.get(..., default)` 都返回它的硬编码字面量——`"冲突爆发"`、`"权力碾压"`、`["压抑","升级","爆发","反转"]`、`1`、`"尊严"`。这些字面量，就是这个算子声称"学到"的全部"爆款结构"。

**对产品的后果。** 生成的 prompt 里五条迁移指令中有两条（[graft.py:196](../../flowbeast/vto/graft.py#L196) 和 [graft.py:200](../../flowbeast/vto/graft.py#L200)）会插值 `emotional_payload` 和 `highest_stakes` 相关字段。前者永远是空字符串。于是 GRAFT prompt 的第 3 条指令，一字不改地长这样：

> 3. **情绪载荷保留**: 开场必须触发与原始钩子相同的情绪反应（），但通过"{topic}"的新情境来实现。

prompt 在要求模型保留一个从未被指定的情绪。

## F4 — QualityGate 从来没有返回过 ACCEPT `[REPRO]`

[quality_audit/](../../flowbeast/data/quality_audit/) 里全部 19 条记录：

| 动作 | 数量 |
|---|---|
| ACCEPT | **0** |
| REVIEW | 10 |
| REJECT | 9 |

分数区间 0.2531–0.5195，而 `QUALITY_ACCEPT_THRESHOLD = 0.60`（[config.py:32](../../flowbeast/observe/quality/config.py#L32)）。

题材"一个普通的故事"跑了六次，得分**精确地都是 0.2531**——小数点后四位全同，还是在不同日期跑的。分数是题材字符串的函数，不是生成内容的函数。

[scorer.py](../../flowbeast/observe/quality/scorer.py) 里九个维度全是对 `unit.hook` 做正则关键词计数。`_score_hook_strength` = 长度 + `_STRONG_HOOK_MARKERS` 命中数 × 0.25 + 一个特异性加分。它衡量的是*某些词有没有出现*，从来不是剧本好不好。

**一个通不过自己输出的 gate，不是 gate。** 它是一个多绕了几步的常量。而且因为 `reverse_engineer.py` 把语料入库也走了这个 gate（[`_gate_before_inject`](../../flowbeast/reverse/reverse_engineer.py#L362)），**这个 gate 会拒绝掉你想入库的真实语料。** 这是此刻就摆在代码里的直接矛盾：建记忆的工具，被一个什么都拒绝的打分器把着门。

## F6 — 校准是构造性循环论证 `[REPRO]`

[calibrator.py](../../flowbeast/observe/quality/calibrator.py) 推荐的维度权重是：

```
recommended_weights ∝ |pearson_corr(dimension, total_including_that_dimension)|
```

每个维度都在和一个*包含它自己*的总分做相关。因此这个相关系数有一部分是"部分—整体重叠"的假象，而不是"这个维度能预测多少质量"——这就是经典的 part-whole 膨胀（Pearson 1897；Kronmal 1993）。

在纯噪声上复现：n = 21 时，用**随机生成、毫无意义的**维度分数跑 200 次，依然能稳定复现出同一组权重向量（平均 ρ = 0.423）。`hook_strength` 在 **46%** 的纯噪声试验里排名第一。一个在真值中权重为**零**的维度，能达到 |r| = 0.738。

**后果：** 这些权重不是从数据里学出来的。它们是这个公式的不动点，无论那些维度有没有意义，结果都长得一样。拿真实标注去跑校准器*并不能*修好它——artifact 在估计量里，不在数据里。

## F7 — gate 有 45% 的权重在衡量打分器根本看不到的东西 `[REPRO]`

`ViralUnit` 只有三个字段：`hook`、`pattern`、`emotion`。而 [scorer.py](../../flowbeast/observe/quality/scorer.py) 里九个 `_score_*` 方法**全部只读 `unit.hook`**。按 scorer 里的权重算，那些依赖"unit 根本没有存储的结构"的维度，占了总分 **0.45**。

所以 gate 的输出就是一个字符串字段的函数。两个 hook 相同的 unit，无论结构、情绪曲线、冲突模式差多远，对 QualityGate 来说都一样。这就是 F1 在 schema 层的成因：GRAFT 无法传递 `hook_structure`，因为它检索到的那条记录里根本没有这个东西。

## 综合

FlowBeast 现在有**五个自指循环，没有任何外部锚点**：

1. **语料**是构建者自己的判断，通过表单手输，而且被一个什么都拒绝的打分器把着门。
2. **GRAFT** 传递五个硬编码常量，管这叫结构迁移。
3. **QualityGate** 是对关键词的正则，从来没接受过任何东西，因此它不衡量质量——它衡量词汇量。
4. **校准**的权重来自一个在噪声上会返回同样答案的公式。
5. **Schema** 无法表达 gate 大部分权重本该衡量的那个结构。

这个系统里没有任何一个位置，是"现实"——真实观众的留存、真实的爆款、真实的失败——能够进来的。这就是为什么往前推感觉很模糊。这不是动力问题。**这个系统无法告诉你它有没有在变好。** 每加一个功能，都是加在一台没有反馈信号的机器上。

这把商业化问题重新框定了。直觉是"我得先做出更好的产品才能卖"。正确的读法是：**你卖不掉一个你无法衡量的护城河，也无法改进它。** 花两天修好测量回路，比花四周磨语料更值——因为现在磨语料不产生任何可见的变化。

# Part 2 — 该借用什么

按它服务的能力组织，按采纳顺序排列。每条包含：**是什么 / 为什么是它 / 怎么接进去**。这里没有任何内容与 [capability_map.md](capability_map.md) 重复。

## A. 先让护城河变得可衡量

在系统能分辨好输出和坏输出之前，这份清单上其他所有东西都不重要。目前它做不到（F1–F7）。

### A1. 在导入任何东西之前，先修好"检索/抽取"契约

**是什么：** 不是一个库。是对你自己代码的修改，也是当前性价比最高的两小时。
**为什么：** 花在语料上的每一个小时都流经这条路径。把 30 个剧本导进一条静默返回默认值的流水线，你会得出"语料没用"的结论——而这正是 F2 为你准备好的结论。
**怎么做：**
1. 给 `FP3Retriever.retrieve()` 加 `record_type` 过滤，让 `ViralScript` 和 `PromptAtom` 永远不会混淆，并让 `PromptAtom` 无法被 GRAFT 路径检索到。
2. 让抽取路径**大声失败**：如果检索到的记录没有 `hook_structure`，就抛异常或返回 `graft_applied=False`——绝不回退到字面量。把常量当作"学到的结构"返回，比报错更糟。
3. 修 [test_graft.py:58](../../tests/test_graft.py#L58)，让它对真实索引内容做断言，并补上缺失的 `index → retrieve → extract` 集成测试。
**结论：** 在做任何语料工作之前做这个。它是前置条件，不是一项任务。

### A2. 用人工评分的叙事评分表作为外部锚点

**是什么：** DramaChain Bench 的 5 轴 63 个叶子维度，建立在 17,488 条专业人工评分之上，其 Agentic Judge 的 PLCC 达 0.918 `[V]`。

**为什么是它：** 你现在的计划是拿*你自己*标注的 30 个剧本去校准 QualityGate——这会让打分器变成你自己品味的镜子，没有任何外部验证。DramaChain 的评分表由专业标注者构建，并对人类排序做过验证。它是这个具体领域里唯一可用的外部锚点，而且覆盖全链路（脚本 → 分镜 → 关键帧 → 镜头视频 → 成片），所以你产出的每个阶段它都能打分。

**怎么做：**
1. 把 [scorer.py](../../flowbeast/observe/quality/scorer.py) 里九个正则维度换成 LLM judge，用 DramaChain 的叶子维度（或你跑得起的子集）来提示。
2. 拿他们的人工评分做校准，而不是拿你自己的标注。
3. 让分数保持**可见且有名字**——见 §C3。
4. **把每一次审计持久化成结构化记录**（`{script, dimension_scores, judge_model, rubric_version, timestamp}`），这样现有 19 条审计加上未来每一条都变成一个可重打分的语料集。此后评分表一变，重打分就是一个批处理任务，而不是重跑一遍——这正是 [Inspect AI](https://github.com/UKGovernmentBEIS/inspect_ai)（UK AISI，MIT）提供的能力：`inspect eval --no-score` 存下 transcript，`inspect score --scorer` 之后重新打分。即使不采用这个库，也要采用这个*模式*（生成与评分分离）。

**保留意见：** 维度集与 judge 是*计划发布*。在把路线图押上去之前先确认可获取性。**回退方案：** 如果拿不到，就用论文里公布的轴定义（论文有描述），或者按它推导出一个简化的 10 维评分表，人工标注 30 个剧本。

**对 LLM judge 应该抱什么预期——在动手之前先设定好。** LitBench（[arXiv 2507.00769](https://arxiv.org/abs/2507.00769)）是关于"judge 与人类在创意写作偏好上的一致度"最干净的公开测量：

| Judge | 与人类偏好的一致率 |
|---|---|
| 最好的开箱即用 judge（零样本、未训练） | **73%** |
| 训练过的 Bradley-Terry 奖励模型 | **78%** |

73% 是第一版现实的ceiling。这是*可用*的——远高于现在这个零信息量的打分器——但这意味着分数绝不能当成真值呈现。它是一个有噪声的排序信号。

**三个 judge 偏见陷阱，都有实测，避免成本都很低：**

1. **成对 vs 单点。** 成对评判在仅仅交换两个候选顺序时，会在 **35%** 的 pair 上翻转结论；单点评判的翻转率是 **9%**（[arXiv 2504.14716](https://arxiv.org/abs/2504.14716)）。如果你要比较两个剧本，**两个顺序都跑**，把不一致当作"平局"；或者各自独立打分再比数字。
2. **中文文本上的评分表漂移。** judge 一致率在英语之外会可测量地下降；中文短剧评分表必须在中文剧本上验证，不能假设能迁移。
3. **自洽不等于准确。** 一个 judge 可以完全自洽（跨运行 CAR ≈ 0）却依然是错的（[arXiv 2602.07996](https://arxiv.org/abs/2602.07996)）。自洽性检查不能替代 A3 里的人工标注。

**结论：** 整个调研过程中发现的最高杠杆外部资产。

### A3. 换掉校准统计——并把它锚定到人

**是什么：** 用 `scipy.stats` 处理 [calibrator.py](../../flowbeast/observe/quality/calibrator.py) 里的相关性，同时给权重换一个正确的估计量（F6 已经排除了现在这个）。

**为什么：** `_pearson_corr` 是手写的，不报告显著性。更重要的是，现在的权重公式是循环论证（F6），所以只把 `scipy` 换进去而不换估计量，只会产出同样无意义的权重外加一个 p 值——那比现在更糟，因为它*看起来*很严谨。

**怎么做：**
1. **先修估计量。** 让每个维度与一个**排除该维度自身**的总分做相关；或者干脆放弃相关法，改用回归/排序，对着一个留出的人工标注集拟合权重。 sanity check：在打乱的标签上跑一遍。如果权重在打乱后依然存活，说明估计量还是循环的。
2. **用精确统计，别用渐近近似。** n = 30 时没有空间做正态近似。需要的东西全在 Python 标准库或 `scipy` 里：
   - **Clopper-Pearson** 精确二项置信区间——`scipy.stats.beta.ppf`
   - 判断"A 是否优于 B"的**精确二项符号检验**——`scipy.stats.binomtest`
   - 分数差的**自助法（bootstrap）**——`numpy.random.default_rng().choice`
3. **人工标注 30 个剧本，并报告一致度。** 30 条标注足以检测大效应，也足以算出与 LLM judge 的 kappa。把 kappa 报出来。如果低于约 0.4，说明 judge 测的不是你以为的东西，再多的流水线工作也修不好。

**样本量算术——跑任何 A/B 测试之前先读这个：**

| 目标 | 所需 n |
|---|---|
| "10 个里 7 个偏好 A"——第一丝信号 | **n = 30**（p < 0.05 需要 21/30） |
| 在 5 分制上检测 0.3 分的位移 | **每臂 n ≈ 174** |
| n = 30 时应该跑几个比较 | **一个** |

n = 30 时你只有**一次**比较机会。拿分数去检验*一个*假设。测五个变体再报告赢家，会把表观效应膨胀约 10.6 个百分点（赢家诅咒：5 个标准正态的最大值期望 ≈ 1.163），而在 n = 30 时，这个膨胀比你试图检测的多数真实效应还大。

**这能换来什么：** 一个你能摆到客户面前的数字。"我们的打分器在 30 个人工标注剧本上与专业人类评分者的一致度 κ = X"是一个论断。"我们的 AI 给您的钩子打 87 分"不是。

**结论：** 实现起来微不足道，而它是"打分器"和"演示"之间的差别。

### A4. 衡量语料多样性——用 Vendi Score，不是向量条数

**是什么：** [Vendi Score](https://arxiv.org/abs/2210.02410)——`exp(相似度矩阵的冯·诺依曼熵)`，即一个集合中**有效不同模式的数量**。参考实现 `vendi-score`（MIT）。

**为什么是它：** 语料是护城河，*前提是*它多样。`index.ntotal` 说 60——但它没说这 60 是 60 个不同的模式，还是同一个模式写了 60 遍。考虑到 GRAFT 返回的是常量，"同一个模式写了 60 遍"是当前最可疑的假设，而现在完全没有办法分辨。Vendi 在现有嵌入矩阵上大约 5 行代码，无需训练，返回一个可解释的数字（"你的语料有 4.1 个有效模式，不是 60 个"）。

**怎么做：**
1. 载入现有 FAISS 向量（store 里已经归一化了）。
2. 构建 n × n 余弦相似度矩阵，求特征值，对熵取指数。
3. **把它作为头条数字和 `ntotal` 并列跟踪**——它应该和 gate 分数放在同一个地方（§C3）。"60 个 unit，4.1 个有效模式"就是那句告诉你下一步该干什么的话。
4. **加上 `hook_type` 熵**作为便宜的伴随检查——对语料的 `hook_type` 字段求香农熵。如果 GRAFT 永远返回 `冲突爆发`，这个数字会立刻暴露，连一次生成都不用跑。

**关于范围：** 这是测量，不是新子系统。它不新增任何流水线阶段，除了 `numpy`（你已经有了）不新增任何依赖。

**护栏：** 不要另建一套评估系统。A2 是对 `scorer.py` 内部的*替换*，不是并排新增。A4 是*加到现有 store 上的一个测量*，不是一个新模块。如果它不是在把"正则"换成"LLM judge"，那就是范围蔓延。

## B. 建语料工厂

只在 Part A 之后。目标是把"手打台词"变成自动化流水线，并停止构建一份已经存在的语料。

### B1. 不要建语料——导入它

**是什么：** SkyScript-100M（来自 6,660 部真实短剧的镜头描述、爽点评分、情绪状态、镜头细节）和 M-Drama（9,138 段标注微短剧片段）`[V]`。
**为什么：** 这是当前最大的时间节省项。手工建一个 30 剧本的标注语料要花几周，产出的东西严格劣于已经能下载到的东西。
**怎么做：** 下载，把它们的字段映射到 `ViralScript`，当作一个*参考分布*——而不是你产品的记忆。它们给打分器提供可锚定的对象（A2）。
**保留意见：** 任何商业使用前先核实许可。SkyScript 来自哈工大 + 昆仑/SkyWork；确认发布是否允许商业再分发，并且不要把它作为资产放进你交付的任何东西里。

### B2. 为你*确实会看*的剧自动化台词抽取

**是什么：** 一趟 ASR + 场景检测，替代手工打字幕。
**为什么：** F3。真正卡脖子的是手工那一步，不是分析。
**怎么做：** ASR 和镜头/场景边界检测都有成熟开源方案；具体选型在配套的工具调研里（见 Appendix B）。目标是一条命令：视频文件进 → 草稿 `transcript.txt` + 场景边界出 → 你负责校对而不是转录。
**结论：** 只有当你决定继续自己看剧、自己挖掘时才做。如果 B1 给的东西够了，跳过。

### B3. 规模化时，买抽取而不是自己造

**是什么：** BytePlus `las_short_drama_script_gen`，**约 $0.21 / 输入视频分钟** `[S]`。
**为什么：** 按 $0.21/分钟，一部 90 分钟的剧转成剧本约 $19。比你一小时的时间便宜，而且是字节自己针对短剧调过的模型。
**怎么做：** 把它当作*批量*路径，人工标注只留给你最在意的 20–30 部剧。注意这个讽刺：这正是你原本打算自己造的能力。买它，才是"不重复造轮子"原则的正确应用。
**结论：** 强烈建议买。一批 10 部剧约 ¥140。

## C. 最后一公里——把回路闭到成片

### C1. `decisions/002` 里的边界挡住了验证，应该收窄

[decisions/002](decisions/002_what_we_do_not_do.md) §1 禁止视频生成代码，§4 禁止发布/分析。这些边界当初写下，是为了阻止 FlowBeast 漂移成一个更差的视频工具。

**问题：** 从不产出成片，你就无法观测留存；不观测留存，你就没有反馈信号——而这就是 Part 0 的全部内容。这条规则保护了架构，却饿死了护城河。

**解法：** 一个**薄的、一次性的验证工具**，活在产品之外，永远不被 `flowbeast/` 导入。它调用外部视频 API，发布结果，读回数字，写进 `feedback_ingest`。它是测量仪器，不是功能。把边界划在"这段代码绝不能成为核心的依赖"，而不是"我们永远不渲染视频"。

### C2. 最后一公里要租，不要造

**是什么：** 生成用 Volcengine Ark / Seedance，配音用 DashScope CosyVoice，合成用 FFmpeg。每一个都是租，不是造。
**为什么：** 生成成本在下降，而且会继续下降。MiniMax API 标价 **768p ¥0.50/秒**、**¥0.025/张图**、**TTS ¥3.50/万字符** `[S]`；一集 60 秒的裸视频成本约 ¥30。任何以"我们帮你省生成成本"来定价的人，都把锚点绑在一个正在下降的数字上。租，并且把集成藏在接口后面。
**保留意见：** DramaChain 发现最优配置是 **gpt-5.5-xhigh + gpt-image-2 + seedance-2.0**，3.30 分对 >3.0 的可用线 `[V]`。这是模型选型的有用起点，但它是他们任务分布上的单次基准——标准化之前先在你自己的内容上复验。

#### C2.1 生成器：Volcengine Ark，以及为什么它零集成成本

**是什么：** 通过 **Volcengine Ark** 调用 `seedance-2.0`——`https://ark.cn-beijing.volces.com/api/v3`，兼容 OpenAI SDK `[V]`。
**为什么选它而不是各种聚合商：**
- **`openai>=1.0.0` 已经是依赖**（[pyproject.toml:16](../../pyproject.toml#L16)）。没有任何东西要装；只是改一个 base URL。
- 中国优先：对中国市场的切入点来说，没有跨境支付、没有代理、没有汇率风险。
- **失败不计费**，这在你反复调 prompt 的时候很重要——调优时生成得最多的恰恰是那些失败的。
- Token 计费是公开公式，所以单集成本在按下发送之前就能算出来。
- `camera_fixed` / `ratio` / `duration` 与 `flowbeast/drama/pipeline.py` 已经在输出的 `shots[]` 数组**一一对应**（当前运行是 21 个镜头 / 85 秒）。

**Kling 3.0 是最大化控制力的替代方案** `[V]`：它的多镜头语法原生接受 `shots[]` 列表，与 FlowBeast 自己的镜头数组构成直接的结构匹配——编译器的输出已经是 Kling 输入 schema 的 90%。ToS §6.4 允许商业使用。它在 1080p 下约为 Ark 的 2.4 倍（85 秒 $9.52 vs $5.94），所以它是一个*质量档位*，不是默认值。

**怎么做：** 把渲染层建成**provider 层的兄弟**——`flowbeast/render/`，用 `get_video_backend()` 根据新的 `settings.VIDEO_BACKEND` 分发，镜像 [pipeline.py](../../flowbeast/drama/pipeline.py) 里已有的 `AUDIO_PROVIDER = "edge"` 开关，以及 [flowbeast/core/providers/\_\_init\_\_.py](../../flowbeast/core/providers/__init__.py) 里的 `MODEL_PROVIDER` 分发。把 `ARK_API_KEY` / `ARK_BASE_URL` 加进 [config.py](../../flowbeast/core/config.py)，和已有的各家 key 放在一起。

**结论：** 采纳。这是通往成片最便宜的路径，而且不新增任何依赖。

#### C2.2 旁白与字幕——6 行改动解锁整个"成片"

**这是整个调研集里杠杆最高的发现，而且它不是新工具。它是你自己文件里的一个 bug。**

**是什么：** `edge-tts` 本来就会输出**词级时间戳**，而 [flowbeast/drama/audio.py:79](../../flowbeast/drama/audio.py#L79) 调用了 `await communicate.save(...)`，把它们全扔了。

**为什么重要：** `[V-live]` 我拿 7.3.1（锁定的版本）对 20 个字的台词 `她跪在暴雨里，手里攥着那份亲子鉴定报告。` 实测，返回了 **12 个 `WordBoundary` 事件，带 100 纳秒刻度的偏移量**——例如 `('暴雨', offset=6125000, duration=4375000)` = 0.6125s → 1.05s。这意味着准确的字幕、以及镜头切换与旁白的同步，**今天就能拿到，零成本、零新依赖、零 GPU**——而且比 ASR 更准，因为你本来就知道你让它说的是什么。

**一个对实现很关键的精度问题** `[V-live]`：边界是**词级，不是字级**。`暴雨` 和 `手里` 各自作为单个 token 到达。因此逐字的 `\kf` 卡拉OK需要在 token 的各个字之间插值时长（按比例或均分）。要为此做计划——这是"字幕能用"和"字幕在 2 倍速下看起来是错的"之间的差别。另外已确认：标点（`。`、`，`）会从边界文本中被剥掉，这是字幕必须从源剧本重新对齐推导、而不能从事件拼接的第二个原因。

**怎么做**——全部改动：

```python
communicate = edge_tts.Communicate(text, voice=EDGE_VOICE, boundary="WordBoundary", ...)
submaker = edge_tts.SubMaker()
with open(mp3_path, "wb") as f:
    async for chunk in communicate.stream():
        if chunk["type"] == "audio":
            f.write(chunk["data"])
        elif chunk["type"] in ("WordBoundary", "SentenceBoundary"):
            submaker.feed(chunk)
srt = submaker.get_srt()
```

**两个坑**，都已验证：
1. `Communicate.__init__` 默认 `boundary="SentenceBoundary"`（`communicate.py:335`）。漏掉这个参数，你会静默地拿到句级粒度。
2. **标点会从边界文本中丢失。** 字幕必须通过对齐从源剧本重新推导，不能从边界事件拼接。

**结论：** 采纳——**排在 Part 2 所有其他事项之前。** 目前 FlowBeast 和一个真正做完的成片之间隔着两天工作；这一项把其中大部分去掉了。

**然后是字幕本身：** `pysubs2`（MIT，py≥3.12）→ 带 `\kf` 卡拉OK标签的 ASS → `ffmpeg -vf "ass=cap.ass:fontsdir=/app/fonts"`。[audio_assembly.py](../../flowbeast/drama/audio_assembly.py) **已经在第 68 行和第 93 行 shell 调用 ffmpeg**，所以边际成本就是一个 filter。随附发布 **Noto Sans SC**（OFL）——绝不用微软雅黑（见 A.6）。

**断行是你必须自己搞定的唯一一块** `[V]`：BudouX（Apache-2.0，py≥3.10）加上一张避头尾表，约 50–100 行。现成的东西没有能在无头环境做中文断行的，而没有它，烧进画面的字幕会从词中间断开。

#### C2.3 合成：FFmpeg，以及 Dockerfile 目前是坏的

**是什么：** 以 FFmpeg 为渲染核心——`overlay` → `xfade` → `ass` → `sidechaincompress` → `loudnorm`。
**为什么：** 零许可、零 sidecar、零遥测、一趟完成。`[V-live]` 本机 ffmpeg 6.1.1 带 `enable-libass`，`ass`/`subtitles` filter 可用。**Remotion 的许可悬崖是人头数，不是收入**——≤3 人（含外包）免费，4 人及以上付费 `[V]`；在围绕它做架构之前先把这个决定做了。没有值得用的纯 Python 渲染路径。

**阻塞点：** `[V-live]` Docker 生产阶段是 `python:3.12-slim`，**没有 ffmpeg 也没有字体**，而 `audio_assembly.py` 通过 subprocess 调用 `ffmpeg`。**今天这个交付镜像里的 capture 步骤根本跑不起来。** 一行修好：

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends ffmpeg fonts-noto-cjk \
    && rm -rf /var/lib/apt/lists/*
```

**闪避链（ducking）**，已验证可用——旁白对音乐做 sidechain，让人声保持清晰：

```
[2:a]volume=0.35,aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo[bgm];
[1:a]aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo[nar];
[nar]asplit=2[narmix][narside];
[bgm][narside]sidechaincompress=threshold=0.03:ratio=8:attack=5:release=250:makeup=1:level_sc=1:detection=rms[bgmduck];
[narmix][bgmduck]amix=inputs=2:duration=longest:normalize=0[mixed];
[mixed]loudnorm=I=-14:TP=-1.5:LRA=11[outa]
```

**把 BGM 设计成一个可替换的槽位。** 每个音乐来源都有权利陷阱（A.6）；让音轨在应用内可换，运营者就能直接放进一条他们已经有授权的抖音曲库音轨。

### C3. 把分数做成一个有名字、看得见的产物

**是什么：** OpusClip 的 **Virality Score 0–99**（hook strength、emotional flow、perceived value、trend alignment——Hook/Flow/Engagement/Trend 四个 tab）是人们愿意付 $15–29/月的原因 `[V]`。它是黑盒；一位评测者实测钩子准确率只有约 60–70% `[S]`。**但它依然是产品界面本身。**

**为什么这对 FlowBeast 重要：** QualityGate 目前是内部的、基于正则的，而且 100% 返回 REJECT。市场上没有任何人拥有一个**针对 AI 生成叙事的、可读的、有名字的质量门**——这是 FP3 论点里被抄袭得最少的部分。OpusClip 证明：即使分数不完美，人们也愿意为一个可读的分数付钱。
**怎么做：** 给分数起个名字，在每一份输出上展示它，并展示两次运行之间变了什么。价值在*对比*，不在数字本身。
**结论：** 高。这是包装，不是工程——而且是当前最便宜的差异化手段。

## D. 分发与趋势情报

### D1. 抄 Alison.ai 的 Preflight 模式

**是什么：** Alison 上线了 **Preflight Plus**——免费、**不要信用卡、不连广告账户、约 30 秒出结果**——按 Google 的 ABCD 框架和 Meta/LinkedIn 最佳实践给任意视频打分 `[V]`。一家有融资的公司选择用一个*打分器*作为免费切入点。
**为什么：** 这是这个市场里最干净的 PLG 动作：免费工具就是产品核心能力应用在用户自己的素材上，零上手摩擦，即时出结果。
**怎么做：** 一个公开、免注册的页面：粘贴题材或拖入剧本 → 得到短剧评分和逐维度拆解。在暴露之前先做限流和花费上限（`api/main.py` 目前允许任何访客触发一次真实的 LLM 调用）。
**结论：** 强。对 FlowBeast 现在已经是的这个东西来说，这是转化率最高的形态。

### D2. 卖无人值守的产能，不是单次生成

**是什么：** Revid.ai 的 **"Auto-Mode workers"**——定时、无人值守生产——是一个付费档功能 `[V]`。Revid 还在**每一个套餐**上提供 **API + MCP server + CLI**，包括 $39 那档 `[V]`。
**为什么：** 一次性生成是商品。可重复、定时的产出才是订阅。而且把 API 放在最便宜的套餐上（而不是锁在企业版里），是他们能嵌进别人工作流的方式。
**怎么做：** 一个暴露编译器的极简 MCP server，是在现有 FastAPI 表面之上的少量工作，而且它把 FlowBeast 放进创作者本来就在的 Claude/Cursor/agent 工作流里。`capability_map.md §9` 已经指出 FastAPI 端点就是 webhook/MCP 应该长出来的表面。到 [registry.modelcontextprotocol.io](https://registry.modelcontextprotocol.io/) 注册。

**按杠杆排序，附真实工时估计** `[V]`：

| 表面 | 工时 | 结论 |
|---|---|---|
| **MCP server**（官方 registry） | **8–16 h** | **采纳**——精准触达想要 prompt 编译器的 agent 用户 |
| **Claude Code plugin/skill** | **4–8 h** | **采纳**——几乎免费，同一批受众。*Team/Enterprise 上仅限 owner 提交，而且第一个提交某个 repo 目录的组织永久持有该 listing——请用长期应该拥有它的那个组织去提交* |
| **n8n community node** | 16–40 h | 试用。**硬性要求：从 2026-05-01 起，提交审核的节点必须通过 GitHub Actions 发布并附 provenance 声明——本机发布的会被拒** `[V]` |
| ComfyUI node | 20–40 h | 观望——ComfyUI 用户是图像/视频优先，契合度弱 |
| Dify plugin / Coze plugin | 16–24 h | 观望——Coze 大陆变现需要企业主体 |
| VS Code / Chrome 扩展 | 20–40 h+ | 跳过——与批量编译器契合度差 |

这三个（MCP → Claude Code skill → n8n）共用一个 HTTP client，触达的都是已经在为 AI 工具付费的人。注意和 §3.1 切入点三的对比：`LeCheung/ai-shortdrama-toolkit` 建了一个*营销*漏斗，拿到 0 star；而上面这些是*集成*表面，把工具放进工作本来就发生的地方。

### D3. 把趋势当功能，不要当数据管道

**是什么：** Revid 把**趋势监控按档位切分**——"监控 5 个频道找爆款灵感"vs"监控 50 个"字面上就是一个付费功能 `[V]`。他们还铺了一整面免费 SEO 页面：TikTok Hooks Library、"Most Viewed TikToks (100M Club)"、Viral Video Rankings、TikTok Trends Today。
**为什么：** 趋势数据感觉像一个重型基建项目。竞品把它做成**档位区分**——被监控频道数才是定价轴，不是信号的精细度。
**怎么做：** 从少量人工跟踪的来源开始，在产品 UI 里呈现。在拥有付费用户之前，不要建趋势摄取管道。

### D4. 在中国做发布是浏览器自动化，不是 API

**这是最改变"最后一公里"含义的发现。** §3.2 说复利资产是渠道自有的遥测数据。而这就是横在你和那个渠道之间的东西。

**是什么：** [dreammis/social-auto-upload](https://github.com/dreammis/social-auto-upload)——**15,506★，MIT** `[V]`。通过 CLI 用浏览器自动化上传到抖音 / 视频号 / 小红书 / B站 / 快手（`sau douyin upload-video …`）。

**为什么它是唯一的路** `[V]`：

| 平台 | 官方发布 API | 门槛 |
|---|---|---|
| **快手** | ✅ 有 | **最干净的官方路径。**四条里最干净的——先用这个 |
| **抖音** | ⚠️ 存在 | **注册资本 ≥¥500,000 且企业注册满 1 年。个体工商户被排除。** 这是公司注册问题，不是工程问题 |
| **视频号** | ❌ 无 | — |
| **小红书** | ❌ 无 | — |

**为什么这有战略意义：** 抖音 API 的门槛意味着，通往最大短剧平台的*官方*路径对个人运营者是关闭的，无论你造什么。两个后果：

1. **§3.1 的切入点必须卖给已经过线的团队**，或者走快手，或者用*他们的*企业账号替客户发布。不要设计一个唯一分发路径要求"客户必须是你不是的那种主体"的产品。
2. **浏览器自动化能用，但脆弱，而且违反部分平台的 ToS**——把它当作客户侧的便利，永远不要当作产品 SLA。不要承诺无人值守发布。

**全球范围：** `upload-post`（$16/月，`pip install upload-post`）是一个真 API，有 Python SDK，能映射 `is_aigc` / `containsSyntheticMedia` 字段 `[V]`。对比强烈——在中国之外，这是一个 $16/月就解决了的问题。

**结论：** 面向客户的路径采纳，但**定价和承诺要围绕快手和手动导出**，把抖音自动化当作尽力而为。卡住你的是法律主体，不是代码。

### D5. 合规标识是硬门槛，不是功能

**是什么：** 现在有两部中国法规适用于你产出的每一条 AI 生成视频 `[V]`：

- **《人工智能生成合成内容标识办法》**（网信办，2025-09-01 施行）。**第 4 条要求在起始画面添加标识**——一个明确的、可感知的标记，不是写在文案里的说明。**第 10 条禁止删除或隐匿标识**——所以一条在下游把标识剥掉的流水线，本身就是违规。
- **GB 45438-2025**——规定该标记具体形态的标准。
- **《微短剧发展管理办法》广电总局第 16 号令**，**2026-09-01** 生效——微短剧的播出前审核与节目编号制度。

**为什么这在商业上重要：** 这同时是**风险，也是 FlowBeast 存在的最强论据**。一个默认产出合规、标识正确、元数据正确的视频的工具，卖的是监管安全，不只是速度。中国的短剧团队即将需要这个东西，而他们大多数人现在还在用 DeepSeek + 即梦 + 剪映手工拼流水线 `[S]`。

**怎么做：** 用 ffmpeg `drawtext` 烧上 AI 标识**并且**嵌入 C2PA 元数据（`c2patool`）——C2PA 嵌入还会额外触发 TikTok / Meta / LinkedIn / Pinterest 的自动标注 `[V]`。两者都是 $0，而且都应该在 §C2.3 同一趟 FFmpeg 里完成。**默认开启，不做成选项。**

**一个坦率标注的开放法律问题** `[UV]`：**16 号令第 2 条的措辞指向连续剧，第 33 条第 3 项暗示平台层面处理——因此"非连续的 60–90 秒 AI 故事视频是否算微短剧、是否需要节目编号"尚未确立。** 在这个问题解决之前，不要把合规做成头条卖点。GB 45438-2025 的具体参数（措辞、角落位置、最小字高、透明度、时长）必须在硬编码水印之前从 [openstd.samr.gov.cn](https://openstd.samr.gov.cn) 读原文——不要从二手来源猜。

**结论：** 现在就把标识做进渲染环节。它免费、它是必需的、而且它能卖。

## E. 商业管线——网关、成本、部署

### E1. LiteLLM proxy——以及对 `capability_map.md` 的一处更正

**是什么：** 自托管的 OpenAI 兼容网关（MIT，SOC 2 Type II），前面接 100+ 家厂商。虚拟 key、按 key 的 `max_budget` + `budget_duration`、`rpm_limit`/`tpm_limit`、消费日志、fallback、缓存，以及一个 UI。**它也提供 `/v1/embeddings`。** `[V]`

**为什么：**
- [capability_map.md §7](capability_map.md) 标记手写的 provider registry 是正确的——"✅ 这个写得对, 7 家厂商统一抽象." 这层抽象*确实*写得好。**但它没有实现任何计量层。** `flowbeast/api/main.py` 里没有任何限流、鉴权、预算、配额或 token 计数——我在 `flowbeast/api/` 和 `flowbeast/hooks/` 里 grep 了 `rate.?limit|slowapi|budget|quota|api_key|auth|usage|token_count` 确认过。LiteLLM 就是整个缺失的那一层。
- 它也是让 §D1（免费公开打分器）可以安全上线的前提。现在**任何访客都能触发一次真实的 LLM 调用，没有任何上限。**
- **已核实支持的中国厂商：** `deepseek`、`dashscope`/qwencloud、`zai`（智谱）、`moonshot`、`minimax`、`volcano`/火山——以及 ollama、openrouter、gemini、anthropic、openai。`[V]`

**怎么做：** 起一个 Postgres（Neon 或 Supabase 免费档）→ 部署 proxy → 把 [openai_compatible.py](../../flowbeast/core/providers/openai_compatible.py) 移植到 `litellm.completion(model="deepseek/deepseek-flash", ...)` → 为每个公开表面（Streamlit、API、MCP）各发一个虚拟 key，设 `max_budget: 5`、`budget_duration: "30d"` 和一个 `rpm_limit`。

**成本：** 软件 $0。**4–8 小时。**

**保留意见：** 语义缓存被文档标注为对多轮/agentic 流量不安全——连续轮次相似度约 0.99。FlowBeast 的"题材→包"是单次流程，所以适用；但对任何 agent 或 retry key 都要设 `"cache": {"no-cache": true}`。

### E2. 干掉 Ollama 依赖——"768 维阻塞"是个神话

`capability_map.md §2` 把换 embedding 描述成一个项目：说改了 `EMBED_PROVIDER` 而不重建索引会撞上 FAISS 维度不匹配，并把"换成托管 embedding 厂商 → 按新维度重建索引"列为多步计划。**真实数字：**

```
magic 49784632   d (dims) 768   ntotal 60   file bytes 184365
```

**六十个向量。** `fp3_meta.json` 里 60 条记录。重新 embedding 它们约 12,000 token——**按 Voyage-4-lite 费率是 $0.0002，也就是完全被免费额度覆盖**，运行时间几秒。不存在迁移项目。在下面的免费档之下，embedding 账单**多年为 $0**。

**最好的答案甚至不是一个 API。** `[V]` **fastembed**（Qdrant 的 ONNX Runtime 封装，Apache-2.0）提供 **`nomic-ai/nomic-embed-text-v1.5-Q`——768 维，130 MB ONNX，Apache-2.0**——也就是*你索引现在所基于的同一个模型家族*的量化版。进程内，无 daemon，无 GPU，无 torch，CPU 上每次调用毫秒级。

| **fastembed `nomic-embed-text-v1.5-Q`** | **768** ✅ | **$0，进程内** | **推荐。** 与当前索引同模型家族——*索引形状不变。* 130 MB ONNX。为 serverless 而生 |

**一个有价值的副作用** `[V]`：fastembed 还带 **reranker**（`cross-encoder/ms-marco-MiniLM-L-6-v2`，0.08 GB；`jina-reranker-v1-turbo-en`，0.15 GB），成本可忽略。一趟 reranker 对 §A2 的检索是便宜的质量提升，值得接在同一个接口后面。

**还有一个不值得探索的死路：** Ollama Cloud 存在（$20/月 Pro），但它的目录里**只有对话/生成模型——没有任何 embedding 模型** `[V]`。你当前的调用没有托管 drop-in 替代。

**[store.py](../../flowbeast/fp3/store.py) 和 [config.py](../../flowbeast/core/config.py) 里的三处代码修复：**
1. `FP3Store.__init__` 调用 `embed_text("probe")` 自动探测 `dim`，然后 `load()` 立刻从磁盘覆盖 `self.index`——**每次实例化都浪费一次网络往返。**
2. 因为这个覆盖，切换 provider 会表现为 `search()` 处的 **FAISS 断言**，而不是 init 处。在 `load()` 里加一句显式的 `assert index.d == configured_dim`。
3. `_embed_vendor()` **硬默认到 `"ollama"`**——把它翻过来，让缺失的环境变量大声失败，而不是静默指向 `localhost:11434`。

### F1. 按产出计价，不按席位、不按提示词

**是什么：** 有戏AI 的模式：**¥0.1/秒，单集 <¥10** `[V]`。Submagic 的 API：**$0.23/分钟，上量后降到 $0.10/分钟** `[V]`。Klap：对 clip 做纯量级分档（100/300/1,000），没有积分抽象 `[V]`。

**怎么做：** 把计费单位定义为一份完成的 `prompt_package.json`（或一集成片）。不要引入积分抽象——Klap 那种更简单的量级分档比积分更好懂。

**怎么做：** `ViralScript.characters` 已经有 `transformation_arc` 了。把跨集连续性当作产品能力呈现，而不是一个内部数据结构。

## 3.1 三个候选切入点，按证据排序

## 3.2 建议

**切入点一作为收入引擎。切入点二作为分发表面。切入点三只在它服务切入点一时才做。**

由证据推导出的组合是：**面向中国小型团队，以按集计价的方式交付"陪你一起做"的 AI 短剧生产服务，用免费公开打分器做漏斗顶部。**

理由：
- 团队有预算，而且这个痛点是生存性的，不是愿望性的。
- 按产出计价符合他们本来就在想的成本口径（按集的投流）。
- 免费打分器是在这个具体市场里被验证过的唯一 PLG 形态，而且它同时是你的数据采集仪器。
- 每一次客户交付都会用**真实表现数字**喂给 `feedback_ingest`——这是整个分析里唯一会复利的资产，也是 FlowBeast 目前完全没有的东西。

**不要**定位成卖提示词包（§1.4）。**不要**用"viral genome"话术（§1.3）。

### 关于反馈回路

§1.6 和 §5.5 里那个不舒服的真相：分析过的每一个竞品都是**开环**的——挖掘 → 生成。`feedback_ingest` 是唯一会复利的一步，而反馈回路要求你要么有自己的分发，要么有一个拥有遥测数据的客户。这就是 StoReel 有的东西（融资 $34M、自有平台、创作者分成、声称 D7 留存好 22% `[U]`），VidMob 有的东西（分析过 1,800 万+ 素材，约 $5 亿估值 `[S]`），以及 FlowBeast 一点都没有的东西。

**这就是为什么切入点一必须是服务，不是 SaaS。** 一个 done-with-you 的交付能拿到自助工具拿不到的遥测数据，因为数字回来的时候你在场。这也是对"我怎么获得分发"这个问题的诚实回答：一开始，你用人力去买它。

# Part 4 — 为什么这依然可能失败

按"真正杀死这件事的可能性"排序。

**1. 监管门是硬门，而且它在 2026-09-01 关上。** 广电总局第 16 号令（《微短剧发展管理办法》）把播出前审核和节目编号制度带入生效；网信办的标识规定（第 4 条：起始画面加标识；第 10 条：删除标识本身就是违规）已经适用。这和下面那些市场风险在性质上不同——它不是竞争问题，而是**推荐的中国切入点是否合法可交付**的问题。在合规成为头条卖点之前，必须解决两个开放问题：非连续的 60–90 秒 AI 视频到底算不算微短剧（`[UV]`——16 号令第 2 条指向连续剧），以及 GB 45438-2025 的确切标记参数。**缓解手段是真实的，而且它同时就是机会：** §D5 把标识做成默认交付物，从而把一项监管负担转化成多数手搓流水线没有的卖点。

**2. 名字被一家有融资的竞品占了。** Alison.ai 拥有 "Creative Genome"，a16z 在股东名册上，而且在同一个采购对话里营销 `[V]`。任何"viral genome"框架都会以"某家已有公司的更小版本"进场。

**3. 核心能力正在被大厂商品化。** BytePlus 以 $0.21/分钟卖抽取；阿里云把结构抽取 + 迁移 + 十维质量检查写成*数据库用例* `[S]`。这两家在价格上都打不赢。

**4. 这个回路一个开发者一个周末就能复现。** `hypit` 克隆任意爆款视频并产出 100 个变体 `[S]`。`musabqazi/viral-script-generator` 做了播放量离群评分 → top-500 语料 → pgvector 检索 → 排序生成，一个人 `[S]`。GRAFT/PARASITE 的算子形式主义是真实的设计贡献，但**无法申请专利，而且一旦被描述出来就极易重新实现。**

**5. 语料不独家，而真正重要的指标是看不见的。** 广告抓取 $1.88/千条 `[S]`；DataEye 已经以 ¥3,000/年索引了 25 万部剧 `[V]`。而且**任何地方都不存在竞品商业广告的公开转化或 ROAS 数据**——所有人都在挖同样那些弱代理指标（CTR、点赞、投放天数）`[S]`。

**6. 无论你造什么，分发路径都可能是关着的。** 抖音官方发布 API 要求 **≥¥50 万注册资本且企业注册满 1 年**，排除个体工商户 `[V]`；视频号和小红书完全没有公开 API。通往最大平台的路径是一个公司注册问题——这意味着**切入点必须卖给已经过线的团队，或者走快手。** 见 §D4。

**7. 唯一会复利的资产，需要 FlowBeast 没有的分发。** 如 §3.2。没有渠道的编译器没有飞轮，而没有飞轮，"记忆"就是一个静态提示词库，随平台算法变迁而衰减。

**8. 平台正在吸收这个工作。** 即梦现在原生提供 **Agent 模式 + 画布** `[V]`。Revid 把 API + MCP + CLI 放在最便宜的套餐上，卖 auto-mode worker `[V]`。OpusClip 白送一个爆款评分。当视频工具变成带持久上下文的 agent 表面时，一个粘贴进对话框的包就落后一步了。

**9. 这个前提有一个残酷的基准率。** 中国微短剧 90%+ 由 AI 制作，约 1.3% 回本，Q1 爆款率 0.16%，投流吃掉 70–90% `[S]`。把"经过验证的爆款机制"当作*首要*成功驱动，是被市场数据反驳的。

**10. 第一市场不用你的渠道。** Product Hunt：500 个 SaaS 发布里 487 个死掉；第 2 周流量跌 80%；一项覆盖 9,746 次发布的哈佛研究发现点赞"往好里说是噪声" `[S]`。中国短剧创作者在小红书和抖音。而那个做了双语 SEO、针对即梦/可灵/Seedance 的竞品拿到了 **0★** `[V]`。

**什么能让它变得站得住：** 拥有一个能产出真实表现遥测的渠道（唯一会复利的资产）；选一个语料无法通过网页抓取重建的品类或语言利基；**把反馈回路本身做成产品**——"你的记忆每周都在可测量地变好"是站得住的，"我们挖了 25 万部剧"不是；**把 QualityGate 做成可见的、有名字的产物**，这是这个市场里目前没人做的事；**把监管合规做成默认交付物**——一条标识正确、带 C2PA 元数据的视频，从 2026-09-01 起是法律要求，而多数手搓的创作者流水线满足不了它。
